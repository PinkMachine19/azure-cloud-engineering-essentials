# Progressive architecture record

The course begins with one local ASP.NET Core workload. Important sessions add an architecture snapshot and a decision record describing the change, the responsibility moved to Azure, and the new operational risk.

- Session 2: local process and local filesystem; the developer owns everything.
- Session 3: alternative hosting responsibility boundaries are compared; no deployment changes yet.
- Session 4: an Azure administrative boundary is added: tenant context, subscription, and a tagged resource group.

- Session 1: first-principles model only; no runtime or infrastructure changes.
